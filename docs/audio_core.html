2. Die TDM-Runde — interaktiv

Der Taktzähler cur_voice läuft 0…31 und springt dann zurück. In einem Takt wird genau eine Stimme bedient. Eine Sampleperiode fasst rund 597 Takte, also etwa 18 vollständige Runden.

cur_voice = 0 · Runde 0

Seitenteilung: DSP 0 rechnet links, DSP 1 rechts, beide über alle 32 Stimmen. Deshalb bleibt eine Kaskade innerhalb einer Instanz — Voraussetzung für die Auflösung in einer Periode.

4. Der Biquad-Zustandsautomat — Schritt für Schritt

Eine Stimme, ein Kanal: 14 Zustände. Die Multiplikationen sind um je einen Takt versetzt (Operanden werden geladen, im nächsten Takt verbraucht) — das ist die Pipeline innerhalb einer Stimme. Zwischen den Stimmen gibt es keine.

Zustand 0: nächste Stimme wählen

5. Kanalverkettung und Bypass

v_ctrl[10:9] wählt die Quelle einer Stimme. Damit lassen sich Stufen hintereinanderschalten — der Ausgang einer Stimme wird zum Eingang der nächsten.

Ringschluss beachten: prev_post_sample wird jeden Takt neu geladen. Bei cur_voice = 0 steht dort der Ausgang von Stimme 31. Wer alle 32 Stimmen verkettet, baut deshalb keinen offenen Pfad, sondern eine geschlossene Schleife mit 32 × 12 dB/Oktave und einem Sample Verzögerung pro Stufe. Das kann schwingen. Für eine offene Kaskade muss Stimme 0 auf 00 (eigene Quelle) stehen.

7. Konfigurations-RAM — wer schreibt, wer liest

Drei völlig verschiedene Meister greifen auf dieselben Speicher zu. Das ist der Grund, warum die Arrays so aussehen, wie sie aussehen — und warum manche im Block-RAM landen und andere in Flip-Flops.

Die drei Zugriffe im Vergleich

MeisterZielAdresse kommt vonTaktMuster

TDM (Lesen) Konfig-RAM
(vol, per, ctrl, pred)		 cur_voice_next jeden Takt sequenziell, +1 je Takt
Filter (Lesen) Koeffizienten {proc_ch, coeff_idx} 14 Takte je Stufe sequenziell, feste Stufe

Schreibpfad

Die CPU legt ch und off an, die Dekodierung ist reine Verdrahtung — kein Mux, keine Rechnung:

reg_addr[9:1] → ch = reg_addr[9:5], off = reg_addr[4:1] if (write_once) case (off) 4'd4: ram_vol[ch] <= reg_wdata; // Lautstärke 4'd5: ram_per[ch] <= reg_wdata; // Periode 4'd6: ram_ctrl[ch] <= reg_wdata; // Steuerbits 4'd7: ram_pred0[ch] <= reg_wdata; // ADPCM-Prädiktor endcase

Ein einziger Schreibport, ein Takt, ein Wort. Die Adresse ist ein Registerfeld — deshalb kostet der Schreibpfad fast nichts.

Lesepfad

Gelesen wird jeden Takt, und zwar für eine andere Stimme:

dout_vol <= ram_vol[cur_voice_next]; // 1 Takt später gültig dout_per <= ram_per[cur_voice_next]; dout_ctrl <= ram_ctrl[cur_voice_next]; dout_pred0 <= ram_pred0[cur_voice_next];

Der Index cur_voice_next ist ein Zähler. Fachlich ist das ein Ringbuffer-Lesezugriff — nichts Zufälliges, nichts Datenabhängiges.

Und trotzdem entsteht ein Multiplexer. Ein Zähler als Adresse hilft nur dann, wenn das Array ein echter Speicher ist. Liegt es in Flip-Flops, muss aus 32 möglichen Werten einer ausgewählt werden — ein 32:1-Mux aus LUTs, 16 Bit breit, und zwar für jedes Array.

Ob es Flip-Flops werden, entscheidet allein der Schreibpfad. Zwei getrennt bedingte Byte-Zuweisungen wie if (reg_be[1]) mem[a][15:8] <= … erkennt Quartus nicht als Speichermuster. Seit diese Arrays als Ganzwort geschrieben werden, liegen sie im M10K — 1.751 Flip-Flops weniger, im Filterbuild gemessen.

8. Die DMA-Maschine

Ein einziger DMA-Kanal bedient alle 32 Stimmen reihum. Er hält immer nur eine Anforderung offen — kein Puffer, keine Warteschlange, nur ein Zeiger, der weiterwandert.

Der Zustandsautomat

Die Bedingungen

SignalBedeutung
dma_voice5-Bit-Zähler, läuft 0…31 und springt zurück
dma_activeeine Anforderung ist unterwegs, wartet auf dma_ack
|dma_lendie Stimme hat noch Bytes abzuholen
voice_state[1]Stimme ist PREFILL oder PLAYING — gestoppte werden übersprungen
dma_fifo_fullFIFO hat ≥ 48 Wörter — dann pausiert diese Stimme
48 statt 64. Der FIFO fasst 64 Wörter je Stimme, der DMA füllt aber nur bis 48. Die 16 Wörter Reserve verhindern, dass Produzent und Konsument am selben Zeiger gleichzeitig ankommen. Gleichzeitig weiß der TDM dadurch, dass immer Vorrat da ist.

Was bei einer Anforderung passiert

1. dma_ptr = {ram_ptr[dma_voice], 1'b0} 23-Bit-Wort → 24-Bit-Byteadresse 2. Anforderung an den Chip-DMA-Arbiter, wartet auf ack 3. bei ack: fifo_ram[{dma_voice, dma_wrptr}] <= dma_data ram_wrptr[dma_voice] <= dma_wrptr + 1 ram_ptr[dma_voice] <= dma_ptr + 1 (Wortzeiger) ram_len[dma_voice] <= dma_len - 2 (Bytezähler) dma_voice <= dma_voice + 1

Beim Start einer Stimme

if (dma_need_init[dma_voice]): ram_ptr[dma_voice] <= {cfg_ptr_hi, cfg_ptr_lo[15:1]} // Adresse aus dem Register ram_len[dma_voice] <= {cfg_len_hi, cfg_len_lo} // Länge in Bytes ram_wrptr[dma_voice] <= 0 // frisch anfangen

dma_need_init wird gesetzt bei: Startbefehl, Ablauf der Startverzögerung, und Loop-Neuladen (loop_reload). Der TDM setzt dabei im selben Zug seinen Lesenzeiger auf 0.

Wo im Audio-Block die Fläche sitzt

Nicht in den Rechenwerken, sondern in Register-Arrays mit variablem Index: Jeder Lesezugriff darauf wird zu einem 32:1-Multiplexer aus LUTs. Vier solche Arrays (Volume, Periode, Control, Prädiktor) kosteten zusammen rund 2.000 Flip-Flops und ebenso viele Muxe — bis sie als Ganzwort geschrieben wurden und damit im Block-RAM landeten.
