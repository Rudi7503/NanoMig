  ```powershell

  $fs  = 'D:\programmier_ordner\FPGA\NanoMig\src\impl\pnr\nanomig_tc138k.fs'
  while ($true) {
      $out = & $cli --cable-index 4 -d GW5AST-138C -r 51 2>&1 | Out-String
      if ($out -match 'Detected Flash id') {
          & $cli --cable-index 4 -d GW5AST-138C -r 53 --fsFile $fs --spiaddr 0x000000
          break
      }
      Start-Sleep -Milliseconds 700
  }
  ```

## 5. Gelöste Root-Causes (nicht wieder aufreißen!)
1. **AGA-Lock ohne OSD-Bruch (`b0f0aa4`):** `sysctrl.v` (`CMD 4`) und `amiga.xml` **nicht** zum Locken umbauen – stattdessen die 5 Config-Busse direkt in `top.sv:580-586` hart verriegeln (`AGA`, `68020`, `2MB Chip`, `0 Slow`, `4MB Fast`, `Turbo Both+Data`).
2. **Stuck IDE Read (`nanomig.v:739-905`):** `ide_sdc_rd` / `ide_sdc_wr` waren uninitialisiert und wurden bei `por` / Unmount nicht gelöscht → `sd_rd[4]` hing dauerhaft auf `1` (`FF0100F3`) → blockierte `sd_card.v` `start_any`-Flankenerkennung und überschrieb `sdc_sector` mit `0` für jeden Floppy-Zugriff! Durch Initialisierung + `por`-Reset + dominanten Per-Drive-Unmount-Override vollständig behoben (in V3 Hardware-verifiziert: `ide_rd_cnt = 0x00`, `df0_present = 1`, `df0_size_hi = 0x0D`).
3. **Roter Balken oben rechts:** Kam von `` `define SPR_BRAM_TEST `` in `src/tang/console138k/top.sv:1062` (nicht nur `sprite_engine_dma.v`). Auskommentieren entfernt den Balken sauber (in V3 verifiziert).
4. **`mcu_spi_sync` + `sysctrl @ clk_85m` + `s1→s2→s3` `int_ack`-CDC:** In `iverilog` `12/12` für alle 932 XML-Bytes @ 16/13,333/10 MHz + `48/48` `int_ack` Maske `0x0A`, und auf Hardware in V2 (`2fbc261`) + V3 (`c0477d4`) mit funktionierendem OSD + DF0-Mount (`0000000E / 0000000D`) bestätigt!
