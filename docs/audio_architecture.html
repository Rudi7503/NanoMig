Zwei vollständig parallele Biquad-Filterkerne 2. Ordnung, strikt aufgeteilt nach Stereokanälen (Links/Rechts). Jede Instanz bedient alle 32 Stimmen, sodass Kaskadenketten über alle 32 Stufen ohne Instanz-Grenzüberschreitung in einem einzigen Zyklus aufgelöst werden.

Kern-Spezifikationen

  • DSP 0 Zuordnung: Linker Kanal (Voices 0..31)
  • DSP 1 Zuordnung: Rechter Kanal (Voices 0..31)
  • Arithmetik: Direct Form II Transposed
  • Akkumulator: 34-Bit Fixed-Point Q2.14
  • Koeffizienten: 5 Wörter je Stimme im Block-RAM
Branch: rudi/chain-stereo Bitstream: 00e6a049

Die Dual-DSP Trennung nach Stereokanälen (Links / Rechts)

Im NanoMig Audio-Kern rechnen die beiden Hardware-DSPs nicht nach Stimmenhälften (0..15 / 16..31), sondern strikt nach Stereokanälen. Jede Instanz bedient alle 32 Stimmen auf ihrer jeweiligen Stereoseite.

DSP 0 biquad_inst0

Linker Audio-Pfad (Stimmen 0..31)

Berechnet exklusiv alle linken Audio-Samples sämtlicher 32 Stimmen.

.cur_voice(cur_voice), // 0..31
.filter_en_l(v_flt_l), // 1 = aktiv
.filter_en_r(1'b0), // ungenutzt
.out_pcm_l(biquad0_pcm_l)
Vorteil Kaskade: Verknüpft eine Stimme ihr Signal mit dem Ausgang der Vorstufe (v_input_src = 2'b10), verbleibt die gesamte 32-Stufen-Kette innerhalb dieses einen DSP-Kerns.
DSP 1 biquad_inst1

Rechter Audio-Pfad (Stimmen 0..31)

Berechnet exklusiv alle rechten Audio-Samples sämtlicher 32 Stimmen.

.cur_voice(cur_voice), // 0..31
.filter_en_l(1'b0), // ungenutzt
.filter_en_r(v_flt_r), // 1 = aktiv
.out_pcm_r(biquad1_pcm_r)
Echtes Stereo: Filterkurven, Resonanzen und Dämpfungen können links und rechts völlig unabhängig moduliert werden (z. B. Stereo-Bandpass mit versetzten Grenzfrequenzen).
!
Warum nicht nach Stimmenhälfte teilen? Würde man DSP 0 für Stimmen 0..15 und DSP 1 für Stimmen 16..31 verwenden, müsste bei einer 32-Stufen-Kaskade das Sample von Stimme 15 auf Stimme 16 zwischen den DSP-Instanzen synchronisiert werden. Das erzeugt Pipeline-Hazards, Latenz und Phasenknacken. Durch die Links/Rechts-Teilung läuft jede Kaskade 100% lokal.

Speicheranbindung Option 2: Dedizierter 114-MHz-DDR3-Master

Vollständige Entkopplung der Audio-DMA von Agnus und dem 7-MHz-Amiga-Chip-Bus.

Vorher: Agnus-Chip-Bus Arbitrierung
  • × Audio-DMA konkurrierte mit Blitter, Kupfer und CPU auf 7 MHz.
  • × Starre 2-MB-Grenze (baddr[31:21]) verhinderte Samples im Fast-RAM.
  • × Bei 32 gleichzeitigen Stimmen traten DMA-Underflows und Aussetzer auf.
Jetzt: Option 2 (audio_dma_master.v)
  • ✓ Voller 32-Bit-Adressraum: Samples beliebig im DDR3 Fast-RAM oder SDRAM.
  • ✓ Direkter 114-MHz-Zugriff: DDR3-Speicherzugriffe dauern nur 3–5 Takte.
  • ✓ Null Belastung für Agnus: Der Amiga-Chip-Bus bleibt komplett frei.
// Adress-Routing in audio_dma_master.v:
wire is_ddr = (live_baddr >= 32'h08000000); // Fast-RAM / DDR3 Speicherbereich
wire is_sdr = (live_baddr < 32'h02000000); // Chip-RAM / SDRAM Bereich
// DDR3 Fast-RAM wird im 114 MHz Takt direkt über dma_ddr_* bedient.
// SDRAM wird transparent über sdram_addon_* beansprucht.

32-Stufen Filterkaskade & Routing

Stimme 0 erzeugt das Primärsignal (z. B. Rechteck oder Rauschen). Die Folgestufen 1..31 greifen über das Routing-Bit 10 ($0400) auf den gefilterten Ausgang der Vorstufe zu.

Aktuell ausgewählte Stufe: Stimme 0 (Primär-Generator • DMA aktiv)

Kritische Konfigurationsregeln für Kaskaden:

  1. Stufe 0: Setzt AUD0CTRL[10:9] = 2'b00 (DMA-Eingang) und lädt Sample-Daten aus dem RAM.
  2. Stufen 1..31: Müssen zwingend mit AUDxLEN = 0 konfiguriert werden, damit sie kein überflüssiges DMA anfordern.
  3. Routing-Bit: Post-Filter-Quelle ist Bit 10 (2'b10 ≡ $0400).
